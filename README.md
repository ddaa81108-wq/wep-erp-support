# Abdo ERP Local

منظومة ERP عربية (RTL) لإدارة الديون، الأمانات، المشتريات، المصراوية، الخزينة، استلامات الديون، التقارير، الموظفين، والصلاحيات. هذا المستودع يحتوي **الكود المصدري**؛ ولا يحتوي بيانات التشغيل أو كلمات المرور أو نسخة جاهزة للنشر العام.

> المشروع قيد التطوير والاختبار. لا يُعد رفعه إلى GitHub اعتمادًا للإنتاج أو ضمانًا بخلوه من الأخطاء والثغرات. اختبره وراجع إعدادات الأمان والنسخ الاحتياطي قبل استخدام بيانات فعلية.

## البنية

| المسار | المحتوى |
|---|---|
| `src/client/` | واجهة React وTypeScript، أقسام منفصلة وأنماط العرض |
| `src/server/` | خادم Node.js، API، المصادقة والصلاحيات، وSQLite |
| `src/shared/` | العقود والأنواع المشتركة |
| `tests/` | اختبارات المنطق والخادم والواجهة |
| `scripts/` | البناء، الفحص، النسخ الاحتياطي، الاستعادة، والتشغيل على Windows |
| `deployment/windows/` | إعداد مثبت Windows وتعليمات Windows Server 2025 |
| `public/` | الأصول الثابتة للواجهة |

البيانات المالية تُحفظ في SQLite. الخزينة تقرأ إجماليات الأقسام، بينما حركات النقد النشط تُسجّل من داخل الخزينة. الصلاحيات تُفرض في الخادم، لا بمجرد إخفاء عناصر الواجهة. التحديثات الحية تستخدم SSE.

## المتطلبات والتشغيل للتطوير

- Node.js 24 أو أحدث وnpm على Windows. الإصدارات المقفلة للحزم موجودة في `package-lock.json`.
- لتجربة المتصفح آليًا: متصفح Playwright مثبت (`npx playwright install chromium`).

```powershell
git clone https://github.com/ddaa81108-wq/wep-erp-support.git
cd wep-erp-support
npm ci
npm run dev
```

في نافذة ثانية:

```powershell
npm run dev:web
```

واجهة التطوير على `http://127.0.0.1:5173/erp`، والخادم على `http://127.0.0.1:4310`. عند استخدام قاعدة جديدة، أنشئ حساب المدير الأول من شاشة التهيئة. لا تضع كلمة مرور فعلية في ملفات المشروع أو المستودع. القيم الافتراضية تكفي للتطوير؛ إن احتجت متغيرات بيئة، راجع `.env.example` واضبطها في جلسة التشغيل. الخادم لا يحمّل ملف `.env` تلقائيًا. يتطلب فتح النظام اتصالًا بالإنترنت وفق سياسة التشغيل الحالية.

للتشغيل من نسخة الواجهة المبنية بدل خادم Vite:

```powershell
npm run build:web
npm start
```

## الفحص والبناء

```powershell
npm run build
npm run check
npm run test:coverage
npm run test:ui
npm run test:realtime
npm run test:collections-ui
npm run test:zero-review-ui
npm run test:restore
```

`check` يشغّل فحص TypeScript وESLint والاختبارات. شغّل البناء أولًا لأن اختبارات HTTP والواجهة تستخدم ملفات `dist/web`. اختبار الواجهة يشغّل خادمه وقاعدته المؤقتة بنفسه ويحتاج Chromium الخاص بـPlaywright؛ لا يحتاج تشغيل خادم التطوير. اختبار الاستعادة يستخدم مخطط التطبيق الكامل وبيانات مالية تجريبية ويقارن الجداول والأرصدة بعد الاستعادة، ويفحص رفض التلف وحماية النسخة الجديدة عند فشل تنظيف النسخ القديمة. أوامر البناء تخرج إلى `dist/`، وهو غير مرفوع إلى Git. تنفذ GitHub Actions هذه الفحوص على Windows وNode.js 24 عند الدفع إلى `main` وعند طلبات الدمج.

المخطط الحالي 45. الترقية الأخيرة تضيف مراجعة إدارية لتصفير ديون العملاء، مرتبطة بنسخة الحركة المالية، دون تغيير الأرصدة أو السجلات القديمة. الكروت الصفرية القديمة تبقى في وضعها السابق؛ الكروت الجديدة أو التي تصل إلى الصفر بعد التحديث تنتظر المراجعة قبل نقلها إلى مجموعة المسدد. اختبار `test:zero-review-ui` ينشئ 2000 كارت و6000 حركة في قاعدة مؤقتة ويختبر المراجعة والصلاحيات والمزامنة والعرض على الهاتف والكمبيوتر بالمظهرين، ويسجل القياسات في `artifacts/zero-review/metrics.json`.

تحتفظ المنظومة ببصمات طلبات المعاملات ومفاتيح مقارنة أرقام الهاتف وبصمات SQL للترحيلات. تكرار طلب مالي قديم بلا بصمة يُرفض مع طلب مراجعة العملية الموجودة قبل المحاولة، لمنع تنفيذها مرتين. التقارير اليومية تتحدث داخل معاملة الحفظ وتستخدم توقيت المؤسسة، بما فيه التوقيت الصيفي للقاهرة؛ التقارير المقفلة السابقة لا يُعاد حسابها تلقائيًا.

## تثبيت Windows Server 2025

راجع [دليل تجهيز Windows Server 2025](deployment/windows/README-Server2025.ar.md) قبل التثبيت. بناء المثبت يحتاج Inno Setup 6 وملفات runtime الموثّقة في [TOOLCHAIN.md](TOOLCHAIN.md) داخل `vendor/runtime/`؛ هذه الملفات التنفيذية الكبيرة **غير مرفوعة** إلى GitHub. لذا الاستنساخ وحده يكفي للتطوير، لكنه لا يكفي لبناء مثبت Windows دون تجهيز تلك الملفات والتحقق من بصماتها.

لا تعرّض خادم Node أو قاعدة SQLite مباشرة للإنترنت. إعداد الشبكة المحلية وHTTPS والخدمات موثّق في [OPERATIONS.ar.md](OPERATIONS.ar.md). الوصول من خارج الشبكة يحتاج بنية نشر آمنة مستقلة.

## البيانات والنسخ الاحتياطي

المصراوية تحفظ تلقائيًا وتبدأ يومها 04:00 بتوقيت ليبيا، مع انتقال الرصيد السابق تلقائيًا وتصحيح سبعة أيام سابقة لمن لديه صلاحية الكتابة. لا يلزم اعتماد أو حفظ أو ترحيل يدوي. ترقية 44 تحافظ على افتتاحيات الأيام القديمة وصفوفها وتسجل الفروق اليدوية القديمة. راجع [دليل التشغيل](OPERATIONS.ar.md) وحدود الصلاحيات والنسخ قبل التثبيت.

قاعدة التطوير الافتراضية في `var/abdo-erp.sqlite`، وقد تُنشأ بجانبها ملفات WAL وSHM. هذه الملفات والنسخ الاحتياطية والسجلات وملفات الشهادات والأسرار مستبعدة من Git. **لا تنسخ قاعدة مفتوحة يدويًا**؛ استخدم أدوات النسخ والاستعادة المخصصة في `scripts/` واختبر الاستعادة قبل الاعتماد على النسخ.
