# تحسينات الأداء المحلية — المرحلة الأولى

هذه تغييرات في موقع ERP وخادمه، ولا تغيّر Flutter أو الحسابات أو صلاحيات المستخدمين أو البيانات المالية.

## التغييرات

- `Server-Timing` للردود JSON والملفات الثابتة: `total` زمن الخادم حتى تجهيز الرد، و`gate` زمن فحص الاتصال، و`app` ما بعد الفحص. لا تشمل الأرقام زمن الإنترنت أو تنزيل الرد، ولا تُحفظ بيانات المستخدمين أو أجسام الطلبات.
- أداة `npm run measure:network` تقرأ `/api/health` و`/erp` محليًا وعبر الدومين. لا تسجّل الدخول ولا تنفّذ معاملات. الافتراضي ثلاث عينات متتابعة، مع مهلة 15 ثانية للطلب. للمقارنة الدقيقة، تُعاد من جهاز المتضرر وقت البطء. أول طلب قد يتضمن إنشاء اتصال TLS جديد.
- تحميل آخر ملفّي تنسيق للوحة الاستلامات مع قسم الاستلامات، بدل تحميلهما عند البداية. لم تتغير قواعد CSS نفسها أو ترتيبها. Vite ينتظر CSS قبل إظهار القسم.
- دمج حدثَي `focus` و`visibilitychange` المتزامنين في تحديث واحد خلال 16 مللي ثانية. أحداث المعاملات المكتملة لا تمر بهذا التأخير. إغلاق الجلسة يلغي التحديث المؤجل.
- ميزانية للبناء: CSS الأولي لا يتجاوز 450 KiB، إضافة إلى ميزانية JavaScript السابقة 250 KiB.

## استخدام القياس

```powershell
npm.cmd run measure:network -- --samples 3 --output var/network-check.json
```

تظهر أرقام الخادم الجديدة بعد نشر التحديث فقط. نتائج Cloudflare قد تضيف توقيتاتها أيضًا. ردود الملفات الثابتة المخزنة في CDN لا تمثل زمن الخادم الحالي؛ استخدم `/api/health` غير المخزّن لهذا الغرض.

## حدود النتيجة

انخفض CSS الأولي من 463844 إلى 447367 بايت (نحو 3.6%). الجزء المؤجل 16478 بايت، ويُحمّل عند الحاجة؛ هذا تخفيف محدود للبداية، وليس وعدًا بنسبة مماثلة في سرعة الموقع كله. الضغط والتخزين المؤقت للملفات الثابتة كانا يعملان أصلًا.

جرت مطابقة القواعد المجمّعة قبل الفصل وبعده بعد توحيد التصغير، وكانت متطابقة. تُختبر واجهتا الإدارة والموظف، والوضعان الليلي والنهاري، والتنسيقان الأصلي والزمردي. الاختبارات المالية تستخدم قواعد اختبار معزولة.

لم يُغيّر إعداد النفق أو الشبكة، ولم تُزَد فترات المزامنة، ولم يُضف تخزين مؤقت للأرصدة. الاستعلامات التي قيسَت كانت سريعة؛ لا مبرر لتعديل حساباتها دون دليل إضافي. يبقى تشخيص مسار الشبكة من أجهزة المستخدمين مطلوبًا إذا استمر بطء الدومين.

## التحقق المنفّذ

- فحص الأنواع وESLint: ناجحان. اختبارات Node: 310 ناجحة، دون إخفاق أو تخطٍّ.
- بناء الواجهة والخادم وميزانيات الملفات: ناجح.
- لوحة الاستلامات: 96 حالة عرض واختبار عمليات للإدارة، و60 حالة للموظف، مع النهاري/الليلي والأصلي/الزمردي ومقاسات متعددة.
- اختبار الشبكة داخل المتصفح يؤكد عدم تحميل CSS الاستلامات في شاشة العملاء، وتحميله مرة واحدة عند فتح الاستلامات وإعادة استخدامه عند العودة إليها.
- اختبارات الأداء والحفظ: نجاح التنقل مع تأخر الرد، وبقاء النموذج معطّلًا إلى أن تُتحقق بياناته، وظهور الإضافة والتصحيح المؤكدين عند فشل القراءة دون تكرار.
- اختبارات كفاءة الشبكة: اتصال أحداث مشترك، وإرسال صف الحساب المتغير، واستعادة التحديث بعد انقطاع الاتصال مع الاحتفاظ بالمسودة.
- الخدمات الفعلية بقيت تعمل والرد الصحي `ready`، وبقي الإنتاج على الكوميت السابق `b79fcaf`. لم تُنشر هذه التغييرات أثناء التحقق.
