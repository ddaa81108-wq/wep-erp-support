# دعم العربية والإنجليزية — 22 أكتوبر 2026

دعم اللغتين يعمل في النسخة المحلية. العربية هي الافتراضية؛ زر اللغة موجود في بوابة الدخول والقائمة الجانبية وصفحة إعدادات النظام ومراقبة قاعدة البيانات. الاختيار يخص المتصفح الحالي، ولا يغيّر لغة أجهزة الموظفين الآخرين.

## السلوك

- العربية RTL والإنجليزية LTR، مع انعكاس القائمة الجانبية واتجاه حركة شريط الديون.
- يُحفظ الاختيار في `abdo-erp-language`، ويحمل رابط التبديل أيضًا معامل `lang=ar` أو `lang=en`.
- التبديل يعيد تحميل الواجهة بشكل مقصود لتهيئة القوائم الثابتة والأقسام المؤجلة والتواريخ باللغة نفسها. لا توجد إعادة تحميل دورية جديدة.
- يتوقف زر اللغة أثناء طلبات الحفظ. يمر التبديل بحراس حفظ المسودات الحاليين، وتظهر مطالبة تأكيد عند وجود تغييرات في نموذج لم تُحفظ.
- تتغير العناوين والأزرار والفلاتر والتلميحات والرسائل وتنسيقات عرض التواريخ. تبقى مواعيد اليوم المحاسبي والإقفال والنسخ الاحتياطي وفق قواعد المنظومة وتوقيت ليبيا.
- لا تترجم أسماء العملاء والموظفين أو الملاحظات التي أدخلها المستخدمون. لا تتغير الأرصدة أو الصلاحيات أو معرّفات الأقسام والعملات والعمليات.
- أنواع المشتريات القياسية تحتفظ بالقيم الأصلية في الطلبات والسجلات؛ الترجمة عند العرض فقط. الأنواع المخصصة تبقى كما كتبها المستخدم.
- رسائل API تُعرض بالإنجليزية وفق رمز الخطأ الثابت، دون تغيير عقود API أو رسائل السجل على الخادم.
- إشعارات الخلفية تدعم اللغتين وتحتفظ باسم المنفذ. يُخزّن في ذاكرة تفضيلات المتصفح رمز اللغة فقط، ولا تُخزّن ردود API أو البيانات المالية. تحديث عامل الإشعارات المثبّت سابقًا يخضع لدورة تحديث المتصفح المعتادة.
- النسخة المثبتة كتطبيق تستخدم ملف manifest إنجليزيًا عند اختيار الإنجليزية. الهوية VIB Abdo Company واحدة في اللغتين.

## التنظيم والصيانة

`src/client/i18n/language.ts` يحدد اللغة والاتجاه والتنسيق ودالة `uiText`، و`english.ts` يضم أكثر من ألف عبارة ومجموعات الاستبدال `{0}` و`{1}`. يُحمّل قاموس الإنجليزية عند الحاجة قبل تهيئة أقسام الواجهة؛ لا تتطلب الترجمة أي خدمة خارجية أو إرسال بيانات العملاء.

عند إضافة نص واجهة جديد، استخدم `uiText('النص العربي')` وأضف ترجمته إلى القاموس. للجمل ذات البيانات استخدم `uiText('بواسطة {0}', [name])`؛ لا تترجم الاسم نفسه ولا تستخدم `uiText` لقيم البروتوكول أو الحقول المخزنة. يمكن استخدام مفتاح سياق ثالث للكلمات متعددة المعاني مثل `دخول` في بوابة الدخول وسجل النقدية.

يعتمد تركيز خانة قيمة المعاملة على `data-ledger-amount`، وليس على النص المترجم لتسمية الحقل. هذا يمنع تعطل التركيز عند تعديل ترجمة التسمية لاحقًا.

## التحقق

- فحص المشروع: 150 اختبارًا ناجحًا، مع TypeScript وESLint.
- بناء الواجهة والخادم ناجح؛ حزمة الدخول نحو 184.28 KiB ضمن حد 250 KiB.
- اختبار اللغتين على بيانات مستقلة: دخول عربي/إنجليزي، خطأ كلمة مرور مترجم، حفظ تفضيل اللغة، كل الأقسام على الكمبيوتر والهاتف، إدخال معاملة بالإنجليزية، ثم العودة للعربية ومقارنة البيانات المخزنة.
- اختبار القاموس يتحقق من وجود كل مفاتيح الترجمة المستخدمة وعناوين الأقسام المشتركة، وحفظ متغيرات الجمل دون تحريف.
- اختبار عامل الإشعارات يتحقق من اللغتين وبقاء اسم الموظف وعدم إضافة تخزين لطلبات API.
- اختبارات التركيز وترتيب طلبات سجل الأستاذ واشتراك إشعارات المتصفح ناجحة.

الأوامر: `npm run check`، `npm run build`، `npm run test:languages-ui`، `npm run test:ui`، `npm run test:push-ui`، `npm run test:ledger-focus-ui`.

صور فحوص اللغتين ببيانات اختبار موجودة في `artifacts/languages`، والسجلات في `artifacts/i18n-*.log`. لا يتضمن هذا العمل نشرًا على السيرفر أو رفعًا إلى GitHub.
