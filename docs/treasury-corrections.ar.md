# تصحيح معاملات النقدية في الخزينة

إضافة متوافقة مع واجهة API الحالية، مع ترقية قاعدة البيانات 58. الترقية تضيف جدول التصحيحات وفهارسه فقط، ولا تعيد حساب الأرصدة أو كتابة الحركات القديمة.

- الإجراء للإدارة فقط، بما فيها التحقق الخادمي. صلاحية الموظف `treasury.write` تسمح بالدخول والخروج، ولا تسمح بالتصحيح.
- المعاملة الأصلية تبقى بقيمتها وتاريخها ورصيدها التاريخي. تُعرض عليها إشارة «تم تصحيحها» وتفاصيل آخر تصحيح؛ جميع التصحيحات محفوظة في قاعدة البيانات وسجل التدقيق.
- الفرق = الأثر الصحيح الجديد ناقص آخر أثر مصحح، أو أثر الأصل إن لم يسبق تصحيحه. الدخول موجب والخروج سالب. تُضاف حركة فرق الآن مرتبطة بالأصل، وتُحدّث النقدية وصافي الخزينة في المعاملة الذرية نفسها.
- تغيير البيان وحده يحفظ التصحيح دون حركة نقدية صفرية. يزيد إصدار النقدية لمنع الاعتماد على معاينة قديمة.
- حركة الفرق نفسها لا تقبل التعديل؛ التصحيحات اللاحقة تبدأ دائمًا من الأصل وتستخدم آخر قيمة مصححة.
- لا يُكتب أي تغيير في العملاء أو الشركات أو المشتريات أو لقطات الخامسة السابقة. حركات التصحيح لها تاريخ التنفيذ الحالي.

## طلب التصحيح

`POST /api/treasury/cash-entries/{originalEntryId}/corrections`

الجلسة وCSRF وإصدار API مطلوبة مثل سائر الكتابات. لا تغيير في تسجيل الدخول.

```json
{
  "requestId": "unique-correction-uuid",
  "expectedVersion": 10,
  "expectedEntryRevision": 0,
  "direction": "in",
  "amountUnits": 500,
  "description": "القيمة الصحيحة",
  "reason": "أُضيف صفر بالخطأ"
}
```

`expectedVersion` من `cashVersion` عند فتح النافذة. `expectedEntryRevision` من `entry.correction.revision` أو صفر. المبلغ عدد صحيح موجب بالدينار الليبي، والسبب إلزامي حتى 500 حرف.

نجاح 200 داخل `data`: `correctionId`, `entryId`, `revision`, `adjustmentEntryId` (قد يكون null إذا لم تتغير النقدية), `deltaUnits`, `activeCashUnits`, `cashVersion`, `eventSequence`, `replayed`.

إعادة الطلب نفسه بمعرّفه ومحتواه نفسيهما ترجع النجاح السابق دون كتابة أو نشر حدث ثانٍ، حتى لو تغيّر الرصيد بعد ذلك. إعادة المعرف بمحتوى مختلف ترجع 409 `REQUEST_ID_REUSED`.

أهم الأخطاء: 403 `PERMISSION_DENIED`، و404 لحساب في مؤسسة أخرى أو معرف مفقود، و409 `CASH_CORRECTION_CHANGED` عند تغير نسخة المعاملة، و409 `VERSION_CONFLICT` عند تغير النقدية. القيم غير الصالحة والسبب الناقص والحركة التصحيحية المستهدفة بدل الأصل وعدم تغيير البيانات ترجع 400 دون كتابة.

## قراءة السجل والمزامنة

مسار السجل الحالي يضيف حقلي `correction` و`correctionOf` دون تعديل القيم القديمة:

- `correction`: آخر نسخة صحيحة بالقيمة والاتجاه والبيان والسبب واسم المراجع والتوقيت ورقم المراجعة، أو null.
- `correctionOf`: معرف الأصل وتسلسله لحركات فرق التصحيح، أو null.

حدث `treasury.changed` يتضمن `action: cash_corrected` و`entryId` و`cashVersion`. الموقع يحدث الأصل إذا كان في صفحات تاريخ محملة، مع الحفاظ على موضع القراءة. إعادة الاتصال تحدث التاريخ المحمل أيضًا.

في الواجهة، ضياع الرد يجمّد بيانات التصحيح ويتيح إعادة نفس الطلب. التعارض يتطلب إعادة فتح النافذة من الحالة الحالية. الإلغاء قبل الاعتماد لا يرسل طلب كتابة.
