# المطابقة المالية للقراءة فقط

تعيد الأداة بناء الأرصدة من مصادرها، وتكشف الاختلافات دون إصلاحها تلقائيًا. لا تغيّر قواعد العملات أو التقريب أو التحصيل أو حركة الخزينة، ولا تنشر تعديلًا على السيرفر.

## التشغيل

شغّل من مجلد المشروع باستخدام Node 24 أو أحدث، مع حساب Windows المصرّح له بقراءة القاعدة:

```powershell
npm.cmd run verify:financial -- 'C:\ProgramData\AbdoErpLocal\data\abdo-erp.sqlite' '.\var\financial-reconciliation\my-new-report.json'
```

يجب أن تكون القاعدة موجودة، وأن يكون مسار التقرير جديدًا وينتهي بـ `.json`. يمكن حذف معامل التقرير للاكتفاء بالملخص. لا تطلب الأداة كلمات مرور التطبيق، لأنها تعمل محليًا بصلاحيات ملف القاعدة؛ لا تضفها إلى مسار عام أو تمنح الملف لمستخدم غير مصرح له.

تفتح اتصال SQLite مستقلًا بـ `readOnly` و`query_only`، وتستخدم معاملة قراءة واحدة حتى لا تخلط نتائج من لحظتين أثناء عمل الموظفين. لا تستدعي الترحيلات أو تنظيف البيانات أو دوال العرض التي تنشئ حسابات أو أيامًا. لا تتطلب إيقاف الخدمات. قد تطيل القراءة الاحتفاظ بملف WAL أثناء الفحص؛ شغّلها خارج وقت الذروة إذا كبرت القاعدة كثيرًا.

يمكن تشغيل نفس الأمر يوميًا من مهمة Windows موجودة، لكن هذا التعديل لا ينشئ مهمة مجدولة ولا يغير إعدادات الجهاز. نتائج الأداة محفوظة محليًا؛ لا تُرسل إلى GitHub أو خدمة خارجية.

## ما الذي تتحقق منه؟

- الحسابات العادية في الأقسام الأربعة: الرصيد الافتتاحي للدورة النشطة + الديون − السداد، بعد مراعاة سعر التحويل المسجل لكل قيد واستبعاد الملغى والمحذوف. تُحسب النتائج بـ BigInt وتُقارن بالرصيد المخزن. تُجمع الديون والأرصدة الدائنة والصافي لكل قسم ومؤسسة بصورة منفصلة.
- كارتا المصراوية وفودافون داخل الأمانات المصرية: من القسم المصدر، وليس من قيود عميل عادي. تُراعى فروق الافتتاح التاريخية المحفوظة في المصراوية.
- المشتريات: إعادة حساب الناتج من القيمة وسعر التحويل بطريقة التقريب الحالية، ثم الباقي وإجماليات اليوم والترحيل إلى الأيام التالية. أول افتتاح مسجل مدخل عمل معتمد، وليس صفرًا مفترضًا. لا تُجمع أرصدة كل الأيام فتتكرر الديون المرحلة.
- الخزينة النقدية الفعلية: سلسلة دخول وخروج مستقلة، مع التحقق من الرصيد قبل كل حركة وبعدها ورقم التسلسل ورصيد الحساب النهائي. لا يُشترط أن تساوي إجمالي التحصيل المعتمد.
- التحصيلات: ربط الإيصال المعتمد بإقرار القيد الأصلي المحفوظ، ومراجعة المبلغ والنوع والعميل وعدم استعمال قيد واحد لإيصالين. تبقى القيود الأصلية قابلة للفحص بعد إغلاق يوم التحصيل وإزالة صفوفه. يثبت سجل الاعتماد رقم القيد، وأي تصحيح أو إلغاء لاحق يجب أن تفسره سلسلة تدقيق متوافقة مع القيد الحالي؛ وإلا تظهر حاجة للمراجعة.
- سلامة SQLite والمراجع، والنطاق العددي الآمن للعرض. يستخدم التقرير أرقامًا صحيحة ممثلة كسلاسل عشرية، حتى لا تضيع دقة الأعداد في JSON.

إذا لم يوجد سعر تحويل للأمانات المصرية مع وجود رصيد غير صفري، يبقى المقابل بالدينار والصافي `null` وتظهر حاجة للمراجعة. لا يُخترع سعر أو مقابل صفري.

## قراءة النتيجة

| الحالة | المعنى |
|---|---|
| `matched` | اجتازت البيانات المفحوصة الاختبارات المحددة دون فرق أو دليل ناقص |
| `mismatch` | اختلاف حسابي أو مرجعي أو مبلغ يتجاوز نطاق العرض الآمن |
| `needs_review` | لا يلزم وجود فرق حسابي؛ هناك دليل ناقص، أو تعديل تحصيل غير مفسر، أو سعر تحويل مفقود |

رموز الخروج عند تشغيل `node scripts/reconcile-financials.ts` مباشرة: صفر للمطابقة، 2 للفروق، 3 للمراجعة، و1 لفشل التنفيذ أو قاعدة غير مدعومة. قد يختصر npm رموز الفشل إلى 1؛ اعتمد على `status` في الملخص/التقرير للتمييز.

يتضمن التقرير توقيت بدء اللقطة ونهاية الفحص، وعدد المقارنات، والفروق الموقعة بصيغة `المخزن − المتوقع`، وعدّادات السجلات، والنتائج حسب المؤسسة والعملة. تُحفظ أول 200 ملاحظة من كل نوع، مع العدد الكامل وإشارة إلى الاختصار. لا تظهر أسماء العملاء أو أرصدتهم في ملخص الطرفية؛ التقرير التفصيلي يحتوي معرّفات وقيمًا مالية ويجب إبقاؤه في مكان خاص.

## حدود النتيجة

هذه مطابقة اتساق داخلي، وليست شهادة بأن كل معاملة تمثل واقعة صحيحة أو اختبارًا لمنع كل تلاعب. الأرصدة الافتتاحية وأسعار التحويل مدخلات عمل، وسجل التدقيق الحالي ليس سجلًا موقّعًا خارج الجهاز. الرواتب واللقطات التاريخية الثابتة للتقارير خارج نطاق هذا الفحص. لا تعني مطابقة فترة معينة أن القاعدة لن تتغير بعدها؛ تُجرى مطابقة جديدة عند الحاجة.

## التحقق

تغطي الاختبارات بيانات سليمة وفروقات مقصودة، والدفعات المعلقة والمعتمدة والمصححة وبعد إغلاق اليوم، والمشتريات المحذوفة والترحيل، والكروت المرتبطة، وسعر الصرف المفقود، ودقة BigInt وعزل المؤسسات. اختُبرت لقطة WAL مع كتابة من اتصال آخر أثناء الفحص، وحماية الملف الأصلي ومنع استبدال التقارير.

```powershell
node --test tests/financial-reconciliation.test.ts
npm.cmd run check
```
