# تنظيم أدوات اختبار Android

هذه الأدوات محفوظة مع المشروع، لكنها لا تدخل تلقائيًا في بناء الإنتاج أو نشره. تسجيلها في Git لا يشغّلها ولا يعيد إنشاء الحسابات أو تشغيل النفق.

## الأدوات والمستندات

| الملف | الغرض |
| --- | --- |
| `android-staging.ts` | إنشاء أو استئناف قاعدة اختبار مصطنعة على المنفذ 4311؛ يولّد كلمات المرور محليًا. |
| `build-android-staging.mjs` | تجميد نسخة تشغيل للاختبار وفق مرجع مجموعة البيانات. |
| `install-android-staging-admin.ps1` | إعداد مهمتي Windows لبيئة الاختبار ونفقها؛ يتطلب مراجعة صريحة قبل التشغيل. |
| `android-reconciliation.ts` | تنفيذ معاملات مطابقة على قاعدة الاختبار المصطنعة؛ ليس فحص قراءة فقط. |
| `verify-android-staging-public.ts` | التحقق من دخول الاختبار العام ومقارنة مرحلة المطابقة المحددة. |
| `generate-android-contract.mjs` | توليد توثيق من المصدر وأدلة اختبار سابقة. |
| `package-android-handoff.mjs` | تجميع مستندات وأدلة التسليم التاريخي؛ لا يشمل بيانات الدخول. |
| `../docs/android-integration/` | تسليم تاريخي بتاريخ 23 أكتوبر 2026؛ لا يُعد عقدًا محدثًا تلقائيًا. |

الأدوات تحتفظ بمساراتها الأصلية حتى لا تنقطع المراجع الموجودة. بعض الفحوص والتجميعات مخصصة لمرحلة تسليم بعينها؛ لا تُعد نجاحًا حاليًا قبل إعادة تشغيلها في بيئة مصطنعة مناسبة ومراجعة نتائجها. لم تُشغّل هذه الأدوات أثناء تنظيم الملفات.

## ملفات تبقى على الجهاز فقط

- `var/android-staging/`: قواعد البيانات، الحسابات، كلمات المرور، رمز النفق، إعدادات التشغيل والنسخ المجمدة. المجلد مستثنى من Git؛ ينشئ مشغّل الاختبار صلاحيات Windows قبل كتابة الملفات الخاصة.
- `artifacts/android-integration/`: أدلة المطابقة ولقطات الشاشة وحزم التسليم الناتجة، مستثناة من Git.
- `*.private` و`*.private.json` و`.env*` (باستثناء نموذج `.env.example`): مستثناة صراحة لحماية الأسرار خارج المجلدات السابقة أيضًا.

لا تضف ملفًا مستثنى بالقوة إلى Git، ولا تضع كلمة مرور أو رمز نفق داخل الكود أو التوثيق. بقاء الحسابات على الجهاز هو الترتيب الحالي؛ تسجيل أدواتها لا يشارك بيانات دخولها.

## معنى تقرير البناء

`dirty` يصف حالة مجلد Git **وقت البناء**؛ يشمل التعديلات والملفات غير المتتبعة غير المستثناة. يبقى الفحص كما هو، دون تجاهل تعديلات أو فرض `false`.

بعد تسجيل الأدوات تصبح الشجرة نظيفة ما لم توجد تغييرات أخرى. النسخة المثبتة سابقًا تحتفظ بقيمة `dirty` القديمة إلى أن يجري بناء ونشر جديدان؛ تسجيل الملفات وحده لا يغيّر تشغيل الإنتاج. نسخة Android المجمدة القديمة تحتفظ كذلك ببيانات بنائها التاريخية، وبعض أدوات التسليم القديمة تسجل `dirty: true` تحفظيًا؛ لا تُعدّل هذه الأدلة بأثر رجعي.
